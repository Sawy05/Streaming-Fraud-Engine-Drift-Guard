\begin{abstract}
Modern real-time financial transaction systems process tens of thousands of heterogeneous events per second while operating under severe operational constraints: sub-15-millisecond end-to-end latency budgets, extreme class imbalance ($\sim 1.5\%$ fraud prevalence), and continuous non-stationary distribution shifts driven by adaptive adversarial fraud patterns. Conventional batch-oriented architectures fail to satisfy these requirements due to offline feature leakage during training, uncalibrated objective functions under extreme class skew, high serialization overhead in Python runtime interpreters, and silent performance degradation caused by unmonitored covariate and concept drift. 

This paper presents \textbf{Streaming Fraud Engine \& Drift Guard}, an industrial-grade, end-to-end Machine Learning Operations (MLOps) system that unifies real-time event ingestion, point-in-time correct dual-layer feature storage, low-latency tree-ensemble inference, and continuous automated statistical drift observability. The system integrates Apache Kafka / Redpanda for high-throughput event streaming; Feast with DuckDB/Parquet for strictly point-in-time ($ASOF$) historical feature joins and Redis for sub-millisecond online feature lookups; an analytical Binary Focal Loss LightGBM classifier optimized for Precision-Recall Area Under the Curve (PR-AUC) and compiled into an optimized Open Neural Network Exchange (ONNX) graph; a sub-15ms P99 FastAPI scoring microservice running ONNX Runtime on single-core CPU execution providers; and an automated drift monitoring engine executing two-sample Kolmogorov-Smirnov (KS) tests, scale-normalized Wasserstein-1 distances, Evidently AI reports, and Prometheus alert telemetry. Empirical benchmarks demonstrate an offline PR-AUC of $0.884$, an end-to-end P50 latency of $0.56$\,ms, P95 latency of $1.18$\,ms, and P99 latency of $2.02$\,ms under 2,000+ queries per second, validating production readiness well within the $15.0$\,ms Service Level Agreement (SLA).
\end{abstract}
